## 0. Conventions

**Priority.** P0 release blocker (core typing, first run, window visibility, quit, data loss, security). P1 major feature or common path. P2 minor/edge. P3 polish.

**Run column.** `harness-automatable` = runnable today with `scripts/mac-e2e` (an `H` case either exists as the cited harness ID or needs only a new row in its case table). `harness needs new capability: CAP-n` = needs a capability from section 3. `manual-owner` = needs hardware, physical keys, hearing, a second user/display, OS settings the harness must not touch (guardrails in `99-agent-guardrails.md`, `mac-handoff.md`), or a judgment call.

**Preconditions (PRE-x).**
- PRE-A: test Mac per guardrails (EVKey/OpenKey/other IME quit, macOS Vietnamese input source off, input source ABC U.S., owner idle >= 60 s before synthetic input), VietKB build under test in `/Applications`, isolated test HOME or fresh macOS user, VietKB not running.
- PRE-B: PRE-A + VietKB started through LaunchServices (`open`), Accessibility and Input Monitoring granted to the bundle, default config (Telex), menu-bar icon visible.
- PRE-C: PRE-B + TextEdit plain-text document frontmost, empty, focused.
- PRE-D: PRE-B + `start_minimized=false` (main window open; the harness default).
- PRE-E: PRE-B, no VietKB window open (default `Chạy ẩn`), another app frontmost.

**Oracle for typing.** `vkb_core::simulate_keys` / the corpora in 50, 51, 57 and the rulings in 28 (modern tone `hòa`, old `hoà`). Where two documents disagree (20-spec A4 text vs 28/schema on tone style) 28 and the schema win.

**Source column.** Site section, spec file, or `file:line` at read time. Suspicion IDs (S-nn) refer to section 4; capability IDs (CAP-nn) to section 3.

## 3. Gap list: what the current harness does not cover

**What `scripts/mac-e2e` covers today** (95-e2e-report-mac, final regression 249/249): Telex/VNI typing smoke and edge cases (TX-/VN- IDs) in TextEdit plain/rich, Notes, Stickies, Chrome textarea and omnibox, VS Code, Terminal; the hidden-answer secure dialog; one per-app `enabled=false` rule; GUI smoke (settings window opens, AX status item present, menu opens, V/E icon change, banner absent); stability x10 at three speeds. Guardrails: owner-idle gate, EVKey kill/relaunch, input-source restore, isolated HOME, physical-input watcher, focus guard.

**Structural limits:** (1) the app is launched by `exec` of the binary with a temp HOME, so bundle-level behaviour is not tested; (2) the shell's grants are inherited, so no permission transition can be exercised; (3) only the VietKB main window and status item are looked at, never a second window, z-order or Dock; (4) no setting is changed through the GUI, only through the starting `config.toml`; (5) hotkeys other than ⌃⇧/⌃⇧Z are untested; (6) per-app rules only `enabled=false`; (7) the Notes screenshots show the owner's notes (follow-up already noted).
